## Lessons retained

- Do not present a runtime prototype or copied background as finished authored room artwork. Maintain editable prefab assets as the source of truth.
- Do not identify a reported teleport merely from proximity/guard/fall code when the user reports a specific failure message. Trace exact feedback before changing unrelated save rules.
- Do not infer food respawning from an interaction hint. Availability must describe actual world stock, and collected/held pickups must unregister before inventory callbacks.
- When room dimensions change, review physics, camera bounds, music regions, arrivals, objective routing and prop spacing together. The old 14-unit music region was corrected to follow the widened room bounds during source review.
- An Editor import pass from an earlier asset revision is not evidence that the final layout passed. Keep static checks and pending runtime checks distinct.
